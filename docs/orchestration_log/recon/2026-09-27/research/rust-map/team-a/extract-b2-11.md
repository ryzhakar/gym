## f010976 — RFC: Syntax for embedding cargo-script manifests (2024-04-23, en)

### Questions
- Q: What syntax should embed a cargo-script's dependency manifest inside a single Rust source file: fenced code-block/frontmatter, an extended shebang, ordinary comments, an attribute, a macro, or a generic container format?
  concepts: cargo-script, embedded-manifest, macros, syntax-design; domains_live: core;desktop-cli-ui; positions_seen: fenced code-block / dash frontmatter (accepted); extended shebang; no new lexical structure, treat as a comment; attribute syntax; reuse block-comment syntax; prefer doc-comment approach; attribute+macro combo; generic container/envelope format
- Q: Should the new embedded-manifest mechanism be scoped narrowly to `cargo` only for now, or generalized/tool-namespaced from the start?
  concepts: cargo-script, RFC-process, extensibility; domains_live: core; positions_seen: hardcode to cargo now, generalize later; specify a generalization path in the RFC itself; tie it strictly to the shebang/script use, ignored otherwise by rustc
